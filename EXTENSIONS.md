# Extensions

`wgsl-rs` extensions let downstream crates inspect and modify a shader's WGSL
IR **after transpilation but before type instantiation**. This is the primary
extension point for adding cross-cutting features — derive-driven codegen,
debug instrumentation, layout/offset metadata, slab helpers — without forking
the macro.

Extensions are wired up via the `extensions` attribute on `#[wgsl]` and run
each time the module's IR constructor is invoked (i.e. on every
`wgsl_source()` / `instantiate()` call), in declaration order.

---

## TL;DR

```rust,ignore
use wgsl_rs::{ir, wgsl, WgslExtension};

pub struct NoopExt;

impl WgslExtension for NoopExt {
    fn modify_ir(_module: &mut ir::Module) {}
}

#[wgsl(crate_path = wgsl_rs, extensions = [my_crate::NoopExt])]
mod my_shader {
    pub fn main() -> u32 { 42u32 }
}
```

The trait lives in `wgsl_rs` (re-exported from the crate root) and is defined
in [`crates/wgsl-rs/src/extension.rs`](crates/wgsl-rs/src/extension.rs).

---

## The `WgslExtension` trait

```rust,ignore
pub trait WgslExtension {
    /// Modify the IR module in place.
    ///
    /// This method is called in the IR constructor generated by the `#[wgsl]`
    /// macro, after the module's IR items have been constructed but before
    /// type instantiation (for template modules).
    fn modify_ir(module: &mut crate::ir::Module);
}
```

There is exactly one method to implement: `modify_ir(&mut ir::Module)`. The
module is passed by mutable reference, so you can add, remove, or rewrite any
item. The trait has no associated types and no provided methods — it is
deliberately minimal.

Source: `crates/wgsl-rs/src/extension.rs:51-58`.

## The `extensions` macro attribute

Add one or more paths to the `#[wgsl(...)]` attribute on the module:

```rust,ignore
#[wgsl(
    crate_path = wgsl_rs,
    extensions = [my_crate::ExtA, my_crate::ExtB],
)]
mod my_shader { /* ... */ }
```

Each path must point to a type that implements `wgsl_rs::WgslExtension`. The
`extensions` key is a sibling of `crate_path`, `skip_validation`, and
`validate_with_instantiation_types` in the attribute grammar — see
[`crates/wgsl-rs-macros/src/lib.rs:105-113`](crates/wgsl-rs-macros/src/lib.rs)
for the macro-level definition.

A type that does not implement `WgslExtension` is rejected at compile time
with a clear error pointing at the offending path (see the
[`tests/ui/fail/extensions_not_impl.rs`](crates/wgsl-rs/tests/ui/fail/extensions_not_impl.rs)
trybuild test).

---

## When `modify_ir` runs

For every `#[wgsl]` module, the macro emits a constructor that follows this
order:

1. **Build the base IR** by walking the module's items.
2. **Run each extension's `modify_ir` in declaration order**, on the
   `&mut ir::Module` just constructed.
3. For **template modules** (modules with `module_type_params`), type
   substitution is applied separately, *after* extensions have run — so any
   `ir::Type::TypeParam` you add or pass through is correctly substituted in
   every `instantiate()` call.
4. **Render to WGSL** via `ir::render_module` when `WGSL_MODULE.wgsl_source()`
   is called.

The generated wrapper is essentially:

```rust,ignore
let mut m = /* built IR module */;
<ExtA as wgsl_rs::WgslExtension>::modify_ir(&mut m);
<ExtB as wgsl_rs::WgslExtension>::modify_ir(&mut m);
m
```

Source: `crates/wgsl-rs-macros/src/lib.rs:479-495`.

The practical consequence: **anything an extension adds or rewrites is carried
through every `instantiate()` call** — `modify_ir` runs once during each IR
construction, and the items it adds are then substituted automatically on each
`instantiate()` without the extension needing to re-add them per instantiation.

## Working with `ir::Module`

An `ir::Module` is `pub struct Module { name, items, attrs }` — a name, an
ordered list of top-level items, and any Rust attributes preserved from the
source module. Extensions typically walk `module.items` and push new entries
or mutate existing ones.

### Item kinds

`ir::Item` is an enum over the WGSL top-level constructs: `Struct`, `Fn`,
`Const`, and friends. The full list lives in
[`crates/wgsl-rs-ir/src/types.rs`](crates/wgsl-rs-ir/src/types.rs). Anything
you can write at the top of a `#[wgsl]` module, you can also push from an
extension.

### Preserved Rust attributes

Every IR item, plus every `Field`, `FnArg`, and `Module`, carries a
`Vec<ir::Attribute>` of Rust `#[...]` attributes captured from the source.
These attributes are **never rendered into WGSL** — they exist *solely* for
extension inspection.

`ir::Attribute` is:

```rust,ignore
pub struct Attribute {
    pub path: String,   // e.g. "derive", "repr", "crabslab::slab_item"
    pub args: Vec<String>, // split on commas
}
```

So `#[derive(SlabItem, Clone)]` becomes
`Attribute { path: "derive", args: vec!["SlabItem", "Clone"] }`,
`#[repr(C)]` becomes `Attribute { path: "repr", args: vec!["C"] }`, and
`#[inline]` becomes `Attribute { path: "inline", args: vec![] }`.

This is the primary hook for "find all structs with `#[derive(SlabItem)]`"
style logic: filter on `item.attrs`, not on any dedicated flag. See the
`SlabItemExt` example below.

Source: `crates/wgsl-rs-ir/src/types.rs:9-24` and the
[2026-05-15 DEVLOG entry](DEVLOG.md#2026-05-15-wgslextension-trait-and-ir-attributes).

## Worked examples

### 1. A no-op extension (the canonical smoke test)

The `tests/ui/pass/extensions_basic.rs` test exercises the simplest possible
extension:

```rust,ignore
use wgsl_rs::{ir, wgsl, WgslExtension};

pub struct NoopExt;

impl WgslExtension for NoopExt {
    fn modify_ir(_module: &mut ir::Module) {}
}

#[wgsl(crate_path = wgsl_rs, extensions = [super::NoopExt])]
mod ext_shader {
    pub fn main() -> u32 { 42u32 }
}
```

If this compiles, the extension wiring is correct.

### 2. Injecting helper functions for derived structs

The `SlabItemExt` example from the rustdoc on the trait itself, reproduced
here for convenience:

```rust,ignore
use wgsl_rs::ir;
use wgsl_rs::WgslExtension;

pub struct SlabItemExt;

impl WgslExtension for SlabItemExt {
    fn modify_ir(module: &mut ir::Module) {
        // Find structs with #[derive(SlabItem)] in their attrs.
        let slab_structs: Vec<(String, Vec<ir::Field>)> = module.items.iter()
            .filter_map(|item| match item {
                ir::Item::Struct(s) if has_derive(&s.attrs, "SlabItem") => {
                    Some((s.name.clone(), s.fields.clone()))
                }
                _ => None,
            })
            .collect();

        // Add helper functions for each slab struct.
        for (name, fields) in slab_structs {
            module.items.push(ir::Item::Fn(make_slab_read_fn(&name, &fields)));
            module.items.push(ir::Item::Fn(make_slab_write_fn(&name, &fields)));
        }
    }
}

fn has_derive(attrs: &[ir::Attribute], derive_name: &str) -> bool {
    attrs.iter().any(|a| {
        a.path == "derive" && a.args.iter().any(|arg| arg == derive_name)
    })
}
```

## Why extensions exist

The WGSL spec §14.4.1 defines strict alignment, size, and offset rules for
host-shareable types, and many tooling features (layout metadata, slab
encoding, debug instrumentation) need to know about shader contents *before*
type substitution collapses `T` into a concrete `f32`. The `WgslExtension`
trait is the contract that lets downstream crates sit at exactly that point
in the pipeline without forking the macro.

Two design decisions are worth knowing about:

- **`modify_ir` runs before type instantiation.** This is the whole point —
  extensions can produce IR that still contains `ir::Type::TypeParam`, and
  the substitution step will handle it.
- **Rust attributes are preserved on every IR node, but not rendered.** This
  is what makes derive-driven codegen ergonomic: the source attribute is the
  *signal*, and the extension is the *consumer*. The IR duplicates some
  information already in dedicated fields (e.g. `fn_attrs`,
  `inter_stage_io`); that duplication is intentional.

Both decisions are recorded in the
[2026-05-15 DEVLOG entry](DEVLOG.md#2026-05-15-wgslextension-trait-and-ir-attributes).

## Real-world example: `wgsl-rs-layout`

`wgsl-rs-layout` is the first extension that dogfoods `wgsl-rs` as a
dependency. It lives in a separate crate, depends on `wgsl-rs` for concrete
type definitions (`Vec3f`, `Mat4x4f`, `Atomic<u32>`, etc.), and implements
`WgslExtension` to inject layout/offset metadata into shader IR. It is the
reference example of "an external crate that *uses* the extension system
rather than monkey-patching the macro."

[2026-05-29 DEVLOG entry](DEVLOG.md#2026-05-29-wgsl-rs-layout--a-standalone-extension-crate)

## Constraints and pitfalls

- **Run order is declaration order.** If `ExtA` and `ExtB` both want to
  rewrite the same item, `ExtA` runs first. There is no explicit priority or
  opt-out — keep extensions orthogonal where possible.
- **Type substitution happens *after* `modify_ir`.** Anything you push that
  uses `ir::Type::TypeParam` will be substituted correctly on every
  `instantiate()` call. This is the load-bearing property; don't try to
  outsmart it.
- **Attributes are not in the WGSL output.** They exist for extension
  inspection. If you find yourself wanting an attribute in the rendered
  source, you almost certainly want a different IR feature.
- **Extension types must be visible at the call site.** The generated
  constructor calls
  `<#ext_path as #crate_path::WgslExtension>::modify_ir(&mut m)`, so the
  extension type must be in scope where the `#[wgsl]` attribute is written.
  If it is not, the build fails with a normal "cannot find type" error from
  rustc.
- **Non-`WgslExtension` types are rejected.** Passing a path that doesn't
  implement the trait is a compile error, not a runtime panic — see
  [`tests/ui/fail/extensions_not_impl.rs`](crates/wgsl-rs/tests/ui/fail/extensions_not_impl.rs).
- **Don't rely on `WGSL_MODULE` being mutable.** Extensions only see the IR
  *module* (the `Vec<Item>` payload), not the surrounding `Module` static
  (imports, templates, instantiations). Adding new items is fine; adding new
  top-level modules or imports is not.
- **The trait is re-exported at the crate root.** `use wgsl_rs::WgslExtension`
  works; the underlying module is `wgsl_rs::extension`.
